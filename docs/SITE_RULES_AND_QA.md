# Source Spread 운영 규칙과 QA

이 문서는 노션에서 글을 입력하는 방법과 홈페이지에 표시되는 방식의 기준이다. 홈페이지 코드, 노션 싱크, 자동 검사 중 하나라도 이 기준과 어긋나면 PR의 `Site QA` 검사를 통과할 수 없어야 한다.

## 노션 입력 규칙

### 공개 전 필수 정보

`Published`를 체크하기 전에 아래 항목을 채운다.

| 속성 | 입력 기준 |
| --- | --- |
| Title | 홈페이지에 표시할 제목 |
| From | 원문을 게시한 매체나 출처 이름 |
| Source | 원문 글의 제목 |
| Source URL | 원문 주소 (`http` 또는 `https`) |
| Category | `Design`, `Fashion`, `Tech`, `Sports`, `Culture` 중 하나 |
| Date | 원문이 게시된 날짜 |
| Sort Date | 홈페이지 최신순 정렬에 사용할 날짜 |

`Date`와 `Sort Date`는 역할이 다르다. 수정·재발행한 글을 최신으로 올리고 싶을 때는 `Date`를 고치지 말고 `Sort Date`를 바꾼다. 설명(`Description`)과 슬러그(`Slug`)는 비워두면 싱크가 생성한다.

현재 노션 데이터베이스 직접 입력은 필수값을 막지 않으므로, 공개 전 표의 속성을 확인한다. 누락된 상태에서 `Published`를 체크하면 싱크 검사가 실패해야 하며, 오류에 글 제목과 빠진 속성이 나와야 한다. 노션 폼은 폼으로 제출하는 항목을 필수로 만들 수 있지만, 데이터베이스에서 직접 만든 페이지 입력까지 강제하진 않는다. 폼을 주 작성 경로로 바꾸지 않는 한, 상태 수식/누락 항목 뷰를 보조 안내로 쓰고 싱크 검증을 최종 차단선으로 둔다.

### 본문 작성 규칙

- 문단 첫 줄은 들여쓰지 않는다. 노션의 줄바꿈과 문단 간격은 홈페이지에도 반영한다.
- Divider는 문단 사이 여백을 늘리는 용도다. Divider가 번호나 제목을 만들지 않는다.
- `GQ: 질문` 또는 `00: 답변`처럼 한 문단에 `화자: 대사`를 쓴다. 콜론은 입력 명령 표시이므로 홈페이지에는 나오지 않는다.
- 화자명은 본문과 같은 검정 계열 색으로 표시한다. 발화자와 대사는 한 행에 놓고, 모바일에서도 모든 대사의 본문 시작 위치를 맞춘다.
- `Name:` 형식이 아닌 문단은 일반 본문으로 표시한다.
- 노션의 제목, 굵게, 기울임, 링크, 목록, 인용, 이미지, Divider, Video/Embed 등의 서식을 지원하는 범위에서 보존한다.
- 유튜브 영상은 노션 Video 또는 Embed 블록으로 추가한다. 영상은 반응형 16:9 플레이어로 표시한다.

## 홈페이지 표시 규칙

- 로고는 홈으로 이동하고, GNB 카테고리는 `/category/{slug}` 모아보기로 이동한다. 글은 `/posts/{slug}`로 이동한다. 새 이동에 해시 라우트를 만들지 않는다.
- 홈페이지 제목은 한 줄이다. PC에서 실제 마우스 호버/키보드 포커스일 때만 긴 제목이 흐른다. 모바일에서는 제목을 한 줄로 자르고, 행을 누르면 글을 연다.
- 모바일 목록에는 원문 날짜를 제목 아래 작게 표시하고, 별도 Date 머리글은 숨긴다. 카테고리는 제목 오른쪽에 표시한다.
- PC에서는 Date 열을 표시한다. 홈페이지 글 순서는 Sort Date 최신순으로 한다.
- 홈페이지의 Source 링크는 한 줄로 제한하고 넘치는 글자는 생략한다. 글 상세의 원문 링크도 가로 화면을 밀어내지 않게 제한한다.
- 글 상세의 대화 화자와 본문은 각각 정렬된 두 칸에 놓는다. 모바일에서는 화자 칸 너비를 모든 대화 행이 공유한다.
- 파비콘, manifest 아이콘, iPhone 홈 화면 아이콘을 각각 제공한다.

## 자동 QA와 병합 차단

PR의 `Site QA` 검사는 다음을 자동 확인한다.

1. `posts.json`의 형식, 필수 속성, 허용 카테고리, 날짜·URL, 고유 슬러그와 본문 블록 형식
2. 모든 공개 글의 정적 상세 페이지와 제목/설명/대표 URL 메타데이터 생성
3. 대화 발화자 파싱, 숫자 화자(`00:`), 콜론 제거, 유튜브 URL 변환
4. Chromium에서 모바일 폭 320/375/390/430px와 데스크톱 폭의 목록/글 상세 동작
5. 모바일 날짜와 제목 한 줄, 가로 넘침 방지, 카테고리 이동, 행 탭 이동
6. 발화자가 다른 대화들의 본문 시작 위치 일치, Divider 번호 미생성, 유튜브 iframe 비율과 주소
7. 브라우저 JavaScript 오류 및 글 상세 페이지 누락

검사가 실패하면 수정 PR을 병합하지 않는다. 노션에서 본문을 새로 작성하거나 디자인을 크게 바꿀 때는 실제 iPhone Safari와 Android Chrome에서도 PR 작성자가 추가 확인한다. 자동 Chromium 검사는 실제 기기 글꼴·브라우저 차이를 완전히 대신하지 않는다.

로컬에서 실행:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm qa
```

노션 싱크 워크플로도 생성 파일을 커밋하기 전에 같은 `pnpm qa`를 실행한다.
